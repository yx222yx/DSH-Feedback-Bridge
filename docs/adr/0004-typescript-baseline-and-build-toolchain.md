# Adopt a TypeScript baseline with a minimal tsc + esbuild toolchain

The plugin's Host and Client implementation source moves to TypeScript under a single authoritative tree at `src/` (Issue #14); `lib/` becomes generated output — Host ESM emitted by tsc, the Client ModuleLoader bundle emitted by esbuild — is never hand-edited, and is not committed. The toolchain is deliberately minimal: tsc provides strict type checking for both faces and emits the two Host files, while esbuild is the smallest bundler that can produce the required single classic-script `window.__ModuleLoader__.load({id, factory})` client bundle with a synchronous require and only `react` external. Official DeepSeek Harness and Cordis types are consumed directly from the published `@deepseek-ai/*` packages pinned to `0.1.1-rc.2` (the declared compatibility floor): cordis, dsh-host-webserver, dsh-client-runtime, dsh-client-locale, dsh-client-ui-sidebar, dsh-client-ui-settings, and dsh-client-ui-slots; augmentations load by importing each package's `./client` type subpath, and no local approximation types are needed. `skipLibCheck: true` is on because `dsh-client-runtime`'s declarations import type packages that are not in the plugin's dependency tree; our own code remains strictly checked. The published artifact stays the prebuilt JavaScript `lib/` whitelist (plus cordis.patch.yml, README, LICENSE), so users install and load without TypeScript or a compiler.
