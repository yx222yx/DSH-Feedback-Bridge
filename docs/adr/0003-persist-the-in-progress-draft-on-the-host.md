# Persist the in-progress feedback draft on the Host under DSH_HOME

v0.1 keeps the single in-progress feedback draft recoverable across page reloads and DSH restarts by storing it on the Host at `<DSH_HOME>/dsh-feedback-bridge/draft.json` with the minimal schema `{version: 1, title, scenario, gap, desired, context, updatedAt}`. Writes are atomic (sibling temp file, fsync, then rename over the target — never delete-then-rename), and POSIX modes are hard-asserted at 0600/0700 while Windows relies on Node's rename replacement semantics without an ACL-equivalence claim. Corrupt or unknown-version files are quarantined beside the original path rather than silently overwritten, and draft content never enters logs or the status payload. The Client serializes all Host writes in order and uses a generation token so a save scheduled before a confirmed discard becomes a no-op once the discard lands — a late autosave can never resurrect a removed draft; the beforeunload keepalive POST is a best-effort fallback only and carries no success semantics. v0.1 targets the Web profile only: DSH exposes no reliable profile-identity interface, so other profiles sharing the same DSH_HOME may observe the same draft file, which is recorded as a known limitation rather than handled through fragile profile inference.
